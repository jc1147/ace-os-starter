# Memory Protocol — file-based second brain (active every session)

You have a persistent, wikilinked file-based memory for this project. It is the source of truth across sessions — KEEP IT CORRECT. These rules are hook-enforced, not optional.

1. **Recall first.** Before saying you don't know, or re-deriving a past decision, check the recalled memories and search the project memory dir — or run `node "$HOME/ace/Code/memory-system/recall.mjs" "<topic>"` (a keyword index over EVERY note; also the dedup check to run before you write a new one). Recalled memory is point-in-time — verify a claim still holds against current source before relying on it.
2. **Record durable facts as ATOMIC notes** — one fact per file in the project memory dir, each with frontmatter (`name` / `description` / `metadata.type`: user | feedback | project | reference). The fact's body goes in the note, NOT in MEMORY.md. Every NEW note must also carry `metadata.originSessionId` set to the current session id, so the enforcement gates can attribute it. When you UPDATE an existing note, set `metadata.lastSessionId` to the current session id and leave `originSessionId` untouched (it records the creating session — never restamp it); the gates credit either field.
3. **MEMORY.md is a ROUTER, not a list.** Do NOT add a per-note line for every note — that re-bloats it and caps the brain. A NEW note goes in the TREE: write the atomic note, then regenerate its category MOC + the index (`node "$HOME/ace/Code/memory-system/reindex.mjs"`). MEMORY.md holds ONLY the tree links (the `_MOC-*` MOCs) + a small set of always-on essentials; the COMPLETE per-note index lives in `_MOC-*.md` + `_manifest.json` (uncapped) and is found via `recall.mjs`. PreToolUse hooks HARD-BLOCK a MEMORY.md write over 24.4 KB or a pointer line over ~350 chars. The router model is what gives the brain unbounded capacity — keep MEMORY.md small.
4. **Search before writing (dedup).** Look for an existing note on the topic and UPDATE it rather than create a near-duplicate. Delete notes that turn out wrong; soft-archive superseded ones to a `_sunset/` subfolder (never silently delete real history).
5. **Connect.** Link related notes with `[[wikilinks]]` so the dashboard graph and Obsidian stay connected. A `[[name]]` with no file yet is fine — it marks a note worth writing.
6. **Use the `memory` skill** for the full record / update / recall / archive procedure and the exact note format. Don't save what the repo already records (code structure, git history, CLAUDE.md) or what only matters to this one conversation.
